# @cloudpunks/backstage-plugin-catalog-kubeconfig-fetcher

Frontend module for the new frontend system that adds a card to cluster
entities, where users can download or copy a kubeconfig.

The kubeconfig is read from a ConfigMap in the management cluster through the
proxy of the Backstage kubernetes plugin (`/api/kubernetes/proxy`). The
ConfigMap of the entity `foo` is `<namespacePrefix>foo/<configMapName>`, e.g.
generated by a Kyverno policy or an operator.

> **Security**: every signed-in user can use the kubernetes proxy with all HTTP
> methods. Give the service account Backstage uses read permissions only, and
> only store public data (endpoint, CA certificate, OIDC login) in the
> ConfigMap, never tokens or client certificates.

## Installation

Requires `@backstage/plugin-kubernetes` in the app and
`@backstage/plugin-kubernetes-backend` in the backend.

```console
yarn --cwd packages/app add @cloudpunks/backstage-plugin-catalog-kubeconfig-fetcher
```

With `app.packages: all` the module is detected automatically, otherwise
register it:

```tsx
import kubeconfigModule from '@cloudpunks/backstage-plugin-catalog-kubeconfig-fetcher';

export default createApp({ features: [kubeconfigModule] });
```

## Configuration

```yaml
kubeconfig:
  # cluster of kubernetes.clusterLocatorMethods that holds the ConfigMaps
  managementCluster: mgmt
  # all optional, the defaults are shown
  namespacePrefix: cluster-
  configMapName: oidc-kubeconfig
  configMapKey: kubeconfig
  # text above the buttons, e.g. how to sign in
  instructions: Install the kubelogin plugin before using the kubeconfig.
```

By default the card is shown for entities of kind `Resource` and type
`kubernetes-cluster`. Replace the filter in `app-config.yaml`, e.g. to select
clusters by label:

```yaml
app:
  extensions:
    - entity-card:catalog/kubeconfig:
        config:
          filter:
            kind: resource
            metadata.labels.example.com/cluster-class: { $exists: true }
```
